## 1. 策略工坊

侧边栏「策略库」「多风格组合」「每日信号」「因子研究」属于策略工坊。

### 1.1 数据准备

- 首次使用时，策略库页面会提示「准备数据」：下载沪深300 成分股 + 10 只核心 ETF（约 310 个标的）从 2016 年中至今的日线、300 只股票的财报，以及各股票纳入沪深300 的日期（约 15 分钟）。
- 默认股票池是**全时点版本**（2026-10-09 起）：历史上每一天只在当天的真实成分里选股，包括后来被剔除、已经退市的股票（Baostock 每月成分快照 + 退市股日线），消除幸存者偏差；旧的半时点股票池只保留作对比。
- 之后每个交易日 19:30 自动增量更新；财报 7 天刷新一次。
- 数据存在本地数据库，回测时不再访问网络。

### 1.2 策略库（首页）

每条策略一张卡片，按「验证夏普」从高到低排列：

| 卡片内容 | 含义 |
|---|---|
| 名称、`vN` | 策略名与当前冠军版本号 |
| 缩略曲线 | 冠军版本从训练开始至今的收益（蓝）与沪深300（灰）；浅色底为验证、留出区间 |
| 开发期夏普 | 冠军在开发期（2018～2024）的夏普比率 |
| 折算可信度 | 按该策略至今的尝试次数折算后，冠军真实夏普大于 0 的概率（DSR）。尝试越多、夏普越接近 0，可信度越低 |
| 留出期收益 | 冠军在留出区间（从不参与优化）的累计收益 |
| 最大回撤 | 冠军在开发期的最大回撤 |
| 自动 | 开启后每个交易日晚上自动优化（7 条全开约占用本地显卡 1.5～2 小时） |
| 优化 | 立即让 AI 优化一次（默认 5 轮，可在详情页修改） |

「创建风格策略」一键创建 7 种风格的初始策略：价值投资、趋势跟随、均值回归、ETF 轮动、防御稳健、指数择时、质量成长。初始规则在 `config/strategies.yaml`，可修改后再创建。

「新建策略」创建自定义策略（2026-10-11）：起点为空白或风格模板，选全时点股票池，用表单编辑规则（`SpecEditor`：选股范围、因子、过滤、持仓与权重、调仓、择时、风控，可切换 JSON）；「试算」只回测开发期、不保存、不返回留出期（`POST /api/quant/preview`），避免反复修改时消耗留出期；可选研究模型与每晚自动优化（开启自动优化必须设置研究模型）。

### 1.3 策略详情

顶部：风格说明、研究模型、版本数；右上角可开关每晚自动优化、设置优化轮数、打开「研究设置 / 手动编辑规则 / 因子库 / 归档」。

| 标签 | 内容 |
|---|---|
| 冠军版本 | 中文规则、改动理由与检验结论、收益曲线、开发期 / 其中训练 / 其中验证 / 留出的指标表、分年收益、升级检验（与当时冠军逐年对比的超额、p 值）、稳健性、开发期诊断 |
| 交易明细 | 见 1.4 |
| 资金容量 | 见 1.9 |
| 信号与实时跟踪 | 见 1.6、1.10 |
| 版本历史 | 所有回测过的版本：状态、来源、开发期夏普与回撤、相对冠军的等波动超额与 p 值、留出收益、检验结论。点击打开详情抽屉（含回测报告与交易明细），可「设为冠军」或「以此为基础编辑」 |
| 研究记录 | 长期研究笔记（AI 每轮总结的经验，可编辑）；每次优化的每一轮：AI 的诊断与经验、候选、相对冠军的超额 / p 值 / 逐年胜负、淘汰原因、耗时与 token |

### 1.4 交易明细

回答「交易了哪些股票 / 基金、收益如何、为什么这样交易」。在策略详情的「交易明细」标签查看冠军版本；在任何版本（包括每轮优化中的候选）的详情抽屉里也可以查看。

先选择区间：开发期 / 其中训练 / 其中验证 / 留出 / 全部。持有记录按**卖出日期**归入区间；回测结束时仍持有的只出现在留出和全部中。

| 子标签 | 内容 |
|---|---|
| 概览 | 成交笔数（买 / 卖）、完整持有次数、胜率、平均盈利与平均亏损、平均持有天数、交易盈亏与费用、涉及标的数、调仓与止损次数；**卖出原因统计**（掉出排名、不满足过滤条件、止损、移动止损、择时降仓……各自的次数、平均收益与合计盈亏）；盈亏最多的 10 个标的 |
| 调仓记录 | 每次调仓：T 日收盘 → T+1 执行、可选标的数、选中多少（新买 / 继续持有）、卖出多少、大盘择时状态。展开后：入选标的的**综合排名**（如 3/61）、目标权重、**每个因子的数值和位置**（「前 5%」= 按该因子的方向排在可选标的前 5%）；卖出标的的**具体原因**（如「综合排名降到第 38 名（继续持有需前 15 名）」「不满足过滤条件：均线乖离(60) 大于 0（当前 -0.04）」「从持有期高点回撤 15.3% 触发移动止损」）。止损单独成条 |
| 持仓收益 | 每一次「买入 → 全部卖出」：买入日、卖出日、持有天数、收益率、盈亏金额、卖出原因；可筛选盈利 / 亏损 / 仍持有、股票 / 基金，可按收益或天数排序 |
| 标的汇总 | 每个标的：持有次数、胜率、累计持有天数、最好与最差一次、合计盈亏 |
| 成交流水 | 每笔成交：日期、方向、数量、价格、金额、费用、原因（如「新入选：综合排名第 9/72 名」「权重调整：减仓」） |

校验：所有持有记录的盈亏之和等于期末净值减初始资金。

### 1.5 AI 优化

点击「优化」后，AI 研究员（研究设置中选择的模型）逐轮工作：

1. **阅读**：风格说明、因子库与**因子成绩单**（各因子在开发期的选股能力）、冠军规则、冠军在开发期的完整报告（逐年收益、最深回撤、换手与成本、盈亏最多的标的）、**交易诊断**（胜率、盈亏比、卖出原因、亏损最多的持有）、**长期研究笔记**、升级条件、最近 8 次尝试的结果。
2. **诊断并提出候选**：默认每轮 3 个，每个只做 1～3 处有理由的改动；同时总结至多 3 条经验写入研究笔记。
3. **检验**：开发期回测 → 开发期夏普不高于冠军的直接淘汰 → 参数随机扰动的稳健性检验 → 升级门槛（见 3.3）。
   显著性门槛按**当前冠军以来累计检验过的候选数**收紧（p ≤ 0.05 ÷ 累计候选数），同一个冠军被挑战得越多门槛越高。
4. **升级**：通过者中开发期夏普最高的成为新冠军；其余记为淘汰并写明原因。

程序调参（AI 给结构、程序在训练区间调数字）实测容易过拟合，默认关闭，可在研究设置中开启。

**研究设置**：研究模型、风格说明、回撤上限（默认 25%）、显著性门槛（0.05）、最少持仓（20 只）、换手上限（20 倍）、逐年胜率（50%）、程序调参（默认关）、每轮候选数（3）、每次优化轮数（5）。检验区间与本金在创建后不能修改，否则各版本不可比。

**研究有效性**（「研究记录」标签顶部）：评估「AI 优化到底有没有用」，只用于评估、不参与任何挑选。

- **回测过拟合概率 PBO**：把全部版本的开发期月度收益切成 12 段，每次取一半当「样本内」挑夏普最高的版本，看它在另一半里排名是否落到中位数以下；落到以下的比例就是 PBO。≈ 50% 说明挑「样本内最好」和随便挑没区别（在拟合噪音），越低越好。
- **开发期与留出期夏普的排名相关**：开发期越好的版本，留出期是否也越好。≤ 0 说明改进不能延续。

**手动编辑**：在详情页用表单（或 JSON）修改规格，可先试算开发期；保存后立即回测并检验，但不会自动替换冠军，需要时手动「设为冠军」。

**另存为新策略**（`POST /api/quant/strategies/{id}/fork`，`service.fork_strategy`）：以冠军或任意版本为初始版本建立独立策略，可选复制研究笔记、研究模型、每晚自动优化。检验区间、本金、门槛沿用来源；半时点股票池改为对应的全时点股票池并重新回测。新策略记录来源（`quant_strategies.origin`），并继承检验次数：升级检验的累计候选数在初始版本上加上来源中已与该版本比较过的候选数（`service.prior_tests`），DSR 的尝试次数包括来源在另存时已有的全部版本（沿来源逐级追溯，`service.trial_scores`），避免靠另存清零多重检验校正。

作者实测：使用本地 Qwen3.8-27B 时每轮约 1.5～4 分钟；DeepSeek（deepseek-flash）每轮约 0.5～1.5 分钟、约 0.05 元。

> 实测（2026-10-05，PRD 3.9）：不论沪深300 还是中证800、旧因子还是新因子、本地 Qwen 还是 DeepSeek，各策略全部版本的回测过拟合概率在 0.57～0.83、开发期与留出期夏普的排名相关 ≤ 0.1——「AI 修改单个策略规则」挑出的更好版本在新行情中并不更好。升级门槛会把它们拦下，策略不会因此变差，但也很难通过这种方式变好。

### 1.6 每日信号与实时跟踪

**最新信号**（策略详情 → 信号与实时跟踪）：按最近一个收盘日的数据计算冠军版本的目标持仓；输入资金量后换算成整手股数和金额。策略每 N 个交易日调仓一次，信号表示「如果今天调仓，目标是什么」。

**实时跟踪**：点击「开始实时跟踪」后，系统为该策略建立一个实时模拟账户（本金 100 万，同时设一个买入持有沪深300 ETF 的对照账户）：

- 从下一个交易日起，每个交易日收盘后按冠军版本决策，下一交易日开盘由交易引擎按真实规则成交；
- 调仓节奏与回测一致；冠军更新后自动切换到新版本；非调仓日只检查止损；
- 每天的决策说明包括选股理由（排名与因子位置）和卖出原因；
- 页面显示跟踪以来的收益与基准、净值曲线、最近决策、下一交易日的调仓清单、当前持仓。

**每日信号页**汇总所有跟踪中策略的收益与调仓清单；未跟踪的策略可一键进入详情查看信号或开始跟踪。

实时跟踪是唯一不受历史数据影响的检验，也是判断「能否用于实盘」的主要依据（见 PRD 3.9）。

### 1.7 因子研究

「因子研究」页列出每个因子在股票池全部可选股票上的表现：每隔 20 个交易日，计算因子值与之后 20 日收益的排名相关系数（IC），并按因子分 5 组比较之后的收益。

| 列 | 含义 |
|---|---|
| 平均 IC、ICIR、t 值 | 选股能力的强弱与稳定性；**|t| ≥ 2** 才算统计上可靠 |
| 同向比例 | IC 与平均方向一致的期数比例 |
| 逐年 IC | 每年的平均 IC（红正绿负）；正负翻转说明因子在不同行情中不稳定 |
| 五分组年化 | 按因子从低到高分 5 组的年化收益；整体水平受幸存者偏差影响偏高，应看组间差异 |
| 多空年化 | 按建议方向，最好一组减最差一组 |

可切换开发期（AI 看到的就是这一段）与留出期（仅供参考），以及股票池（沪深300 / 中证800，均为时点版本）。实测 2018～2024 年沪深300 范围内没有任何因子 |t| ≥ 2，单因子选股能力都很弱。

### 1.8 多风格组合

把资金按权重分给几条不同风格策略的冠军版本，在同一个账户中运行：

- **回测报告**：组合在开发期与留出期的收益、夏普、回撤、波动；各成员的表现；成员之间开发期月度收益的相关性（越低分散效果越好）。
- **信号与实时跟踪**：组合目标持仓 = Σ 成员权重 × 成员冠军的目标权重（列出每只股票来自哪些成员）；开始跟踪后在一个模拟账户中运行，各成员按自己的调仓周期更新，成员冠军更新后自动切换。
- 成员需使用同一个股票池，2～10 个，权重自动归一。
- 组合在**同一个账户**中运行：每个成员按自己的调仓周期更新，任一成员调仓时整个账户回到目标比例（成员之间定期再平衡）。回测与实时跟踪规则相同。
- 组合持股多（例如五风格约 90 只），资金太少时部分股票买不起一手、下单笔数也多；请先看「资金容量」中的最低资金。

### 1.9 资金容量

策略详情与组合页的「资金容量」标签：同一个版本在 20 万到 10 亿共 10 档资金下回测（含冲击成本与单笔不超过当日成交额 10% 的限制），列出年化收益、夏普、留出期收益、总成本、冲击成本、平均仓位、**持仓偏离**、买不起一手的次数、受成交额限制的次数。

**持仓偏离** = 每次调仓后 ½Σ|实际权重 − 目标权重| 的平均值，即没有按目标配置的资金比例。资金充足时也有少量偏离（预留现金、涨跌停、停牌），所以以各档中最小的偏离为基准，看资金规模带来的**额外偏离**。

- **最低资金**：额外偏离不超过 3 个百分点的最小资金。低于它，实际持仓与策略目标差别大，模拟结果不可信。
- **可承载资金**：从最低资金（不低于 100 万）起，年化收益下降不超过 1 个百分点、且额外偏离不超过 5 个百分点的最大资金。
- 实测（2026-10-04）：价值投资最低 20 万；三风格稳健（价值 + ETF 轮动 + 防御）最低 50 万、可承载约 3000 万；五风格组合最低 200 万、可承载约 1 亿（100 万时额外偏离 3.9%，开发期年化 7.5%，仅比 200 万时低 0.2 个百分点）。
- 调仓门槛调整后（见 2.3，组合加减仓至少 0.5%）：五风格组合最低 100 万（100 万时额外偏离 2.9%）、可承载约 1 亿；三风格稳健最低 20 万、可承载约 3000 万。门槛放宽后允许持仓在小范围内漂移，所以各档的持仓偏离整体略高。
- 早期版本用「实际买入额 / 计划买入额」判断，但组合会反复尝试几百元的补仓，买不够一手也计入且重复累计，曾把五风格组合误判为「100 万只买到 42%、最低 1000 万」，已改为持仓偏离。

### 1.10 对账、回放校验与健康度

在「信号与实时跟踪」标签：

- **对账与健康度**（实时跟踪账户）：用同一版本、同一时期、同样本金做快速回测，与交易引擎的实际记录比较：两边收益、累计差与年化差、跟踪误差、日收益相关、成交笔数与成交价偏差、期末持仓重合度、权重差异最大的标的，以及两条净值曲线。结论分「一致 / 有偏差 / 偏差较大」。
  健康度把跟踪期表现放到回测历史中比较：最近收益的分位、最大回撤与回测历史最大回撤、对账偏差，结论分「正常 / 关注 / 提醒」。跟踪满 5 个交易日后开始检查。
- **回放校验**：选择开始日期后，用交易引擎把历史行情重放一遍（与实时跟踪完全相同的执行路径），结束后自动对账。不用等实时数据积累就能确认模拟实现是否一致；约 400 个交易日需要 10 分钟左右。
- 实测（2025-01～2026-09，423 个交易日）：价值投资 引擎 +12.9% vs 回测 +13.4%，跟踪误差 0.6%，成交 37 / 37 笔；五风格组合 +17.9% vs +19.5%，跟踪误差 0.9%，均判定「一致」。
- 2026-10-04 调整调仓门槛后重新回放（五风格组合）：引擎 +21.8% vs 回测 +23.2%，年化差 −0.8%、跟踪误差 0.7%、日收益相关 0.998，成交 948 / 969 笔，判定「一致」（旧门槛时两者为 +17.9% / +19.5%，下单减少后收益提高约 4 个百分点，主要来自成本节省）。调整过程中两处引擎差异曾使年化差扩大到 −3.5%，已修正（见架构文档 5.6）。

### 1.11 可实盘检查

策略详情与组合页的「可实盘检查」标签（策略库卡片、组合列表上显示结果）。同时满足以下条件才标记「可实盘」：

1. **开发期跑赢基准（风险调整后）**：2018～2024 夏普高于基准；
2. **留出期跑赢基准且不明显退化**：2025 年以来夏普高于基准，且不低于开发期的一半；
3. **逐年稳定**：开发期完整年份中至少一半跑赢基准；
4. **实时跟踪 ≥ 3 个月且表现正常**：当前版本跟踪满 60 个交易日，健康度不是「提醒」，回测—跟踪对账不是「偏差较大」；
5. **资金规模在容量范围内**：计划资金（有实盘账户时取其初始资金，否则取跟踪本金）在最低资金与可承载资金之间。

第 4 条需要时间积累，之前为「待观察」；任一条不满足为「未通过」。跟踪中的策略与组合每晚自动重新检查，也可以手动「重新检查」。「可实盘」只说明模拟检验通过，不保证未来收益。

### 1.12 实盘对照

侧边栏「实盘对照」。开始实盘后新建一个实盘账户：选择跟随的策略或组合、初始资金、开始日期（可以添加资金转入 / 转出）。

- **成交记录**：手工录入，或导入券商软件导出的「当日 / 历史成交」CSV。自动识别 UTF-8 / GBK 编码与常见列名（成交日期、证券代码、证券名称、买卖标志、成交数量、成交价格或成交均价、佣金、印花税、过户费等），导入前预览识别结果和跳过的行（如红利入账），重复记录自动跳过。
- **对比报告**：实盘与模拟（实时跟踪账户）的收益、收益差（含年化）、跟踪误差、日收益相关和两条净值曲线；
  执行对照逐笔配对实盘与模拟成交（同标的同方向，实盘在模拟之后 0～5 个交易日内），给出平均成交价差（正数表示实盘更差）、价差损耗金额、平均延迟、费用对比，以及**漏做**（模拟有、实盘没有）和**多做**（实盘有、模拟没有）的交易；最新持仓的权重对照。
- 结论：跟踪误差 ≤ 5% 且年化差 ≤ 2% 为「一致」；≤ 10% 且 ≤ 5% 为「有偏差」；否则「偏差较大」。
- 只保存你提供的成交数据，不连接券商，不需要也不保存任何券商账号或密码。

### 1.17 滚动选择检验（walk-forward）

策略详情「研究记录」中，在 PBO 与排名相关之外增加逐年检验：每年年初只用此前的月度收益，按夏普挑出「当时看起来最好」的版本，记录它这一年的收益，并与「一直用初始版本」「所有版本平均」比较（含留出期年份）。挑出的版本平均排名接近 50% 分位，说明版本之间的差异主要是噪音。候选版本都是 AI 看过开发期之后生成的，这只检验「按历史表现排名」能否延续，不是对研究过程的完整模拟。

### 1.18 AI 交易复核（规则 + AI 复核，两个账户并行）

组合页「AI 复核」标签。开启后，在组合的实时跟踪赛道中加入一个「AI 复核账户」，与规则账户本金相同、并行运行：

- **唯一的区别是 AI 的判断**：AI 复核账户每轮直接复用规则账户的决策（同样的调仓时间、目标权重与加减仓门槛），只对本账户将要**新买入**的股票做复核；被否决的股票不买，那部分资金留作现金。卖出与其他调整和规则一致。
- **复核材料**：股票所属行业、哪些成员策略选中、近 5 / 20 / 60 日涨跌、距一年高点、波动，最近 30 天公告标题（巨潮资讯）与最近新闻标题（东方财富）。
- **否决标准**：只在有明确依据的重大风险时否决（立案调查或处罚、退市风险或 ST、审计非标、财务造假嫌疑、业绩暴雷、大股东大额减持或质押平仓、重大诉讼或违约、重大事故、资质吊销、重大资产冻结等）；不因短期涨跌、估值或一般利空否决。模型调用失败时按规则执行并记录。
- **首次决策**：复制规则账户当前的目标持仓并全部复核，之后与规则账户同步调仓。
- **对比**：两条净值（自 AI 复核账户第一天起）、复核 / 否决次数、**被否决与被放行股票之后（执行日开盘至今）相对沪深300 的超额**、每次复核的结论与理由、模型费用。
- 调仓提醒中附带当天的 AI 复核意见（否决了哪些、理由）。
- 全部是开启之后实时发生的交易，不存在「模型记得历史行情」的问题；需要较长时间积累（至少几十次否决）才能判断 AI 是加分还是减分。
- 使用本地模型时，模型服务需要在每个交易日收盘后（约 15:45 起）保持运行；本地模型默认关闭思考过程以控制耗时（实测 8 只股票约 17 秒）。
- 作者的部署：2026-10-08 起，五风格均衡（AI 复核账户 31）与三风格稳健（账户 32）开启了 AI 复核，复核模型为本地 Qwen；页面上的「有效性评估」卡片只对这两个组合显示（预注册写死了组合与账户编号）。
- **有效性评估（预注册 docs/prereg/2026-10-08-ai-review.md，写于首次决策之前）**：主要指标是同一决策日内「放行 − 否决」股票之后 20 个交易日超额的加权差 D（分日置换检验），底线是 AI 账户合计与规则账户合计的累计收益差 ΔR；只在第 120 个交易日（否决事件 ≥ 20 时）与第 250 个交易日各看一次（p ≤ 0.025）；评估期冻结模型、提示与技能。代码 app/quant/review_eval.py（`python -m app.quant.review_eval`），「AI 复核」页显示进度，评估时点之前不计算显著性。

### 1.19 技能（Skill）：安装审批、隔离运行、AI 按需使用、技能市场与 AI 申请

- **总开关**（2026-10-13，开源准备）：配置项 `skills_enabled`。新安装默认关闭；不写时已安装过技能的旧安装保持开启；关闭时设置页隐藏「技能」、技能接口返回提示、AI 复核与自选股监控不提供技能工具。运行要求与隔离方式见 [SKILLS.md](SKILLS.md)。

「配置中心 → 技能」。技能是外部的「说明 + 脚本 / 程序」包（SKILL.md 格式，与 Claude、WorkBuddy 等通用），用来扩展 AI 能查询的资料（如公告全文、业绩预告、资金流向）。用户 2026-10-08 选择的安全边界（方案 A）：**AI 可以搜索、推荐、使用技能，每次安装都要用户批准**。

- **获取与审阅**：从 GitHub 地址、上传 zip 或技能市场获取；只下载、解压、扫描，不执行任何文件。审阅页列出说明、全部文件（类型、大小、sha256，可查看脚本内容）、可执行程序、文中出现的域名与风险提示（如「下载后直接执行」「需要鉴权」）。
- **运行策略**（审批时确认）：允许访问的域名（含子域名，为空即不联网）、AI 可调用的命令入口（如 westock，不经过 shell）、仅限本人的子命令（如 auth）、安装命令（在沙箱中执行）。
- **沙箱**：每条命令在一次性 Docker 容器中运行——不以 root 运行、去掉全部权限、根文件系统只读，只挂载该技能的包（只读）与它自己的工作目录；网络只连着没有外网出口的内部网络，唯一出口是只绑定网关地址的过滤代理，按技能令牌只放行声明的域名，其余拒绝并记录。实测：声明域名可访问、未声明域名被拦截、无法直连外网 / 局域网 / 平台接口、看不到平台数据与密钥。
- **技能终端**：用户本人在沙箱中执行技能命令，用于完成技能自己的鉴权（如 `westock auth status` 后在浏览器中授权，再 `westock auth fetch` 领取）；密钥只存在该技能的工作目录里，AI 调用不了 auth 子命令。终端使用**会话容器**：同一终端窗口的命令 `docker exec` 进同一个容器（限制与一次性容器相同，另加 `--init`），关闭窗口、闲置 15 分钟、卸载技能或服务启停时销毁——因为 westock 的设备号随容器每次运行变化，授权码的签发与领取必须在同一个容器里（一次性容器会报 `dev_id mismatch`）。AI 调用仍每次用一次性容器。
- **AI 按需使用**：AI 复核员的系统提示只列出已安装技能的名称与说明；需要时用 read_skill 读说明、run_skill 调用命令（同样的命令策略与审计），技能返回的内容只作为资料。模型不支持工具调用时退回一次性复核。本地 Qwen 与 DeepSeek 实测均支持。
- **技能市场**：默认接入 Anthropic 官方技能仓库（GitHub）与 SkillsMP 社区索引（公开搜索接口，匿名每天 50 次，结果缓存一天）；可添加其他 GitHub 技能仓库。市场只负责检索，获取后同样审阅、批准。skills.sh 需要 Vercel 凭证、WorkBuddy 技能市场没有公开接口，暂未接入。
- **AI 申请安装**：AI 复核员发现资料不足时，可以搜索市场并提交安装申请（说明理由）；平台立即获取技能包生成审阅页并推送微信（「技能申请」），用户批准后才安装。同一技能的重复申请合并，待处理申请最多 5 个，每批复核最多申请 1 次，AI 每天搜索市场最多 10 次；可在技能页关闭 AI 申请。
- **审计**：每次调用（调用方、命令、退出码、耗时、输出摘要、被拦截的域名）都有记录。

### 1.23 自选股监控

`/watch`。代码 app/watch/service.py，表 watch_items / watch_events，接口 /api/watch*，定时任务每天 21:15（北京时间，含周末）。

- 收集资料：新增的巨潮公告（A 股）、东方财富新闻、实时涨跌与近 5 日涨跌；看过的公告新闻（URL）记在 state.seen（最多 400 条），第一次只看最近 7 天。没有新资料且当天涨跌 < 5% 时不调用 AI。
- AI（默认沿用 AI 复核的模型，本地模型关闭思考过程；有已安装技能时工具模式，最多 6 次查询）找出事件：level 1～3、direction、title、summary、impact、sources（资料编号 → 原文链接）。提示要求只依据资料、不预测涨跌、不给买卖建议。
- level ≥ 推送级别（默认 2）的事件推送微信（通知事件 watch「自选股提醒」，已有通道默认订阅）。AI 失败时不标记已看过，下次重试。
- 自选权重 0～3（默认 1），只给自选倾斜账户用。股票详情页可「加入自选」并显示最近事件。

### 1.24 自选倾斜账户

组合页「自选倾斜」标签。代码 app/watch/tilt.py，与 AI 复核账户相同的孪生账户机制（同一赛道、同本金、复用规则账户的决策）。

- 调仓日：目标 × 自选权重（非自选为 1），按比例缩放回原总仓位；单只 ≤ 原目标 × 3 且 ≤ max(10%, 原目标)，超出部分留现金；不会买入规则没选中的股票；权重 0 的已选股不买也不持有。
- 第一次决策复制规则账户当前的目标（按权重调整）；只在规则调仓的日子调整。决策里记录当时的权重与每只的调整，组合页显示两条净值与最近一次调整。
- 自选权重是当下的偏好，无法历史回测，只能实时对比；规则账户与 AI 复核账户不受影响（AI 复核评估照常）。

### 1.25 快速开始与一句话创建策略（2026-10-13，开源准备）

- **快速开始**（`POST /api/quant/data/quick-start`，管理员）：先准备快速体验股票池 `cn_quick`（上证50 当前成分 + 10 只核心 ETF，约 60 个标的，2016 年起），完成后自动开始准备完整的 `cn_csi300_hist`。实测从点击到可以试算约 4 分钟。完整数据没好之前，`GET /api/quant/data` 额外返回 `quick`（快速数据的覆盖与任务），新建策略对话框可以选快速体验股票池。
- 数据就绪的判断加了一条：股票池中至少一半标的有行情（`data.READY_SHARE`）。否则快速体验下载的上证50（也属于沪深300）会让沪深300 被误判为已就绪。
- **可实盘检查第 0 项「股票池为全时点版本」**：不是全时点股票池（如快速体验）的策略和组合直接「未通过」，说明有幸存者偏差。
- **一句话创建策略**（`POST /api/quant/strategies/draft`，`app/quant/draft.py`）：用自己配置的模型把中文描述翻译成策略规格；提示里给出与 AI 研究员相同的规格说明和因子库；规格经 `parse_spec` 校验，不合法时带着错误重试一次；规格表达不了的条件必须写进 `unsupported`，页面逐条显示。可以「在当前规则上修改」。只生成规则，不回测。作者实测本地 Qwen3.8-27B 一次 46～82 秒。
- **新建前的试算计入测试次数**：新建策略对话框记录每次试算的开发期夏普，创建时一并提交（`trial_scores`），保存在 `origin`（`kind: new`、`prior_tests`、`trial_scores`、`base_version_id`）。初始版本的升级检验按 `prior_tests` 收紧门槛，DSR 把这些试算算作尝试；另存时沿来源继承。
- **历史成分缺失检测**：`coverage` 返回 `pit_ready`（全时点股票池的 Baostock 历史成分记录是否已生成）。获取失败时数据仍可用，但策略库显示警告和「重新准备完整数据」按钮，可实盘检查第 0 项判为未通过。作者实测本机连 Baostock 查到约 150 次时被断开，重新登录也失败，所以才加了这项检测。
- **不配 AI 也能用**：创建风格策略库时研究模型可以不选；策略库页在没有任何模型时提示哪些功能不需要 AI、怎么添加模型（可关闭）。

### 1.27 AI 优化时间线（2026-10-17，开源 v0.2）

### 1.29 策略导入导出（2026-10-17，开源 v0.2）

- **导出**（`GET /api/quant/strategies/{id}/export`，`app/quant/exchange.py`）：冠军版本存成一个 YAML 文件（`format: stockarena-strategy/1`），包含名称、说明、风格、股票池、检验设置、规则（spec），以及 `provenance`：来源平台与源代码地址、原策略名与版本号、导出时的开发期夏普、测试历史（`trial_scores` 累计尝试的开发期夏普、`prior_tests` 当前冠军以来已检验的候选数）。公共策略的其他用户也可以导出。
- **导入**（`POST /api/quant/strategies/import`，策略库「导入策略」）：校验格式和规则（`parse_spec`）→ 新建导入者自己的私有策略，按本平台的数据和交易成本完整回测 → `origin` 记为 `kind: import`，测试历史从文件继承（升级检验按 `prior_tests` 收紧门槛，DSR 把 `trial_scores` 算作尝试），不能靠「导出再导入」把测试次数清零。
- 导入时的提示：本平台没有文件里的股票池（改用默认）、股票池不是全时点、重新回测的开发期夏普与文件相差超过 0.15（数据、股票池或成本不同）、文件里没有测试历史。
- 文件可以手工修改；继承测试历史是一种诚实约定，挡不住故意篡改，所以导入来源会一直显示在策略页上。社区分享的策略文件放在 `community/strategies/`。

### 1.26 westock 数据每日快照（2026-10-17）

- 一致预期（目标价、未来 3 年 EPS / 营收 / 净利润 / PE / PB / 增速）和个股评分（综合、资金、基本面、风险、技术及周 / 月 / 季变动）在 westock 只有当前值、查不到历史，每个交易日 22:00 存一份（23:30 补查当天缺的），为以后做时点正确的研究积累数据。研究时只能使用 `fetched_at` 之后的数据。
- 范围：沪深300 当前成分（先观察一周没有被限流，再考虑扩到中证800）。表 `westock_snapshots`（as_of、symbol、kind、status、解析后的 data、原始文本 raw、fetched_at），原始文本保留以便以后改进解析。
- 只在开启技能功能、且安装并启用了 westockdata 技能时运行，用技能所有者的授权。在批量专用的常驻容器里逐只查询（每次约 1 秒，一天约 8 分钟）；一次查多只实测会握手超时，不用。
- westock 按请求频率限流（返回「请求过于频繁，请稍后再试」，实测一天连续查 600 次时约 50 次被拒）：每次查询之间至少间隔 1 秒，被限流时等 30 秒、60 秒重试；连续失败 10 次，或累计失败 30 次且超过两成，就停止当天的查询；失败和被限流的不保存，补查时再试。快照在 22:00 运行，与收盘后的 AI 复核错开。
- 命令行：`uv run python -m app.quant.snapshots run`（立即运行一次）、`summary`（最近几天的保存情况）。代码 `app/quant/snapshots.py`。

## 2. 策略是怎么描述和执行的

### 2.1 策略规格

每个策略版本是一份 JSON 规格（程序校验后执行，不运行 AI 写的代码）：

| 部分 | 字段 | 说明 |
|---|---|---|
| 选股范围 `universe` | `types`、`symbols`、`exclude`、`exclude_st`、`min_listed_days`、`min_amount`、`industries`、`exclude_industries` | 股票 / ETF、指定或排除代码、排除 ST、上市天数、20 日平均成交额下限（亿元）、只选 / 排除某些申万一级行业 |
| 打分 `factors` | 1～6 个 `{name, params, weight, direction, neutralize}` | 每个因子在可选标的中算百分位（按方向，越符合越接近 100%），按权重平均得综合分；`neutralize: "industry"` 时在同一申万一级行业内排名（比较同行业公司，避免整体押注某个行业） |
| 过滤 `filters` | 0～6 个 `{name, params, op, value}` | 硬条件，不满足的标的不参与打分 |
| 选股 `selection` | `top_n`、`buffer`、`max_per_industry` | 持有前 N 名；已持有的排在前 N+buffer 内继续持有（降低换手）；同一行业最多持有几只 |
| 权重 `weighting` | `method`（等权 / 按得分 / 波动率倒数）、`max_weight` | 单只上限 |
| 调仓 `rebalance` | `every_days`、`min_trade_pct` | 每隔几个交易日调仓；权重变化太小不交易 |
| 择时 `timing` | `enabled`、因子与条件、`exposure_off`、`defensive` | 基准指数满足条件时正常仓位，否则降到 `exposure_off`，剩余资金买防守资产（如国债 ETF） |
| 风控 `risk` | `exposure`、`stop_loss`、`trailing_stop` | 总仓位；相对成本的止损；相对持有期高点的移动止损（收盘判断，次日开盘卖出，到下次调仓前不买回） |

详情页「冠军版本」会把规格翻译成中文规则。

### 2.2 因子库

| 名称 | 因子 | 类型 | 说明 | 参数（默认，范围） |
|---|---|---|---|---|
| `momentum` | 动量 | 价格，可择时 | 过去 window 日涨幅（跳过最近 skip 日，常用于剔除短期反转） | window=60（5～250）、skip=0（0～20） |
| `reversal` | 短期反转 | 价格 | 过去 window 日涨幅的相反数（跌得越多值越大） | window=5（2～20） |
| `volatility` | 波动率 | 价格，可择时 | 日收益率标准差（年化） | window=20（5～250） |
| `downside_vol` | 下行波动率 | 价格 | 只统计下跌日的波动（年化） | window=60（10～250） |
| `ma_bias` | 均线乖离 | 价格，可择时 | 收盘价相对 window 日均线的偏离（>0 在均线上方） | window=20（5～250） |
| `ma_trend` | 均线趋势 | 价格，可择时 | 快均线相对慢均线的偏离（>0 为多头排列） | fast=20（3～120）、slow=60（10～250） |
| `rsi` | RSI | 价格，可择时 | 相对强弱指标（0～100） | window=14（5～60） |
| `drawdown` | 距高点回撤 | 价格，可择时 | 收盘价相对 window 日内最高价的回撤（≤0） | window=60（10～250） |
| `price_position` | 价格位置 | 价格 | 收盘价在 window 日最高最低区间中的位置（0～1） | window=120（20～500） |
| `sharpe_mom` | 夏普动量 | 价格 | 过去 window 日收益均值 / 波动（年化），稳健上涨得分高 | window=120（20～250） |
| `max_ret` | 最大单日涨幅 | 价格 | 过去 window 日最大单日涨幅（彩票效应） | window=20（5～60） |
| `volume_ratio` | 量比 | 价格 | 短期平均成交量 / 长期平均成交量 | short=5（1～20）、long=60（10～250） |
| `amount_avg` | 平均成交额 | 价格 | 过去 window 日平均成交额（亿元），衡量流动性 / 规模 | window=20（5～120） |
| `beta` | 贝塔 | 价格 | 相对基准指数的贝塔系数 | window=120（40～250） |
| `ep` | 盈利收益率（E/P） | 财报 | 滚动 12 个月每股收益 / 股价，即市盈率的倒数（越高越便宜，亏损为负） | 无 |
| `bp` | 账面市值比（B/P） | 财报 | 每股净资产 / 股价，即市净率的倒数（越高越便宜） | 无 |
| `roe` | ROE | 财报 | 净资产收益率（%，年化） | 无 |
| `profit_growth` | 净利润增速 | 财报 | 归母净利润同比增长（%） | 无 |
| `revenue_growth` | 营收增速 | 财报 | 营业收入同比增长（%） | 无 |
| `gross_margin` | 毛利率 | 财报 | 销售毛利率（%） | 无 |
| `debt_ratio` | 资产负债率 | 财报 | 资产负债率（%） | 无 |
| `dividend_yield` | 股息率 | 分红 | 过去 12 个月现金分红 / 股价（%），按除息日计入；ETF 也适用 | 无 |
| `net_margin` | 净利率 | 财报 | 销售净利率（%） | 无 |
| `growth_accel` | 业绩加速度 | 财报 | 本期净利润同比增速 − 上一报告期的同比增速（百分点） | 无 |
| `size` | 总市值 | 财报 + 价格 | 估算总市值（亿元）= 归母净利润 / 每股收益 × 股价；`low` 偏好小盘 | 无 |
| `turnover` | 换手率 | 财报 + 价格 | 平均日换手率（%，按估算总股本） | window=20（5～120） |
| `idio_vol` | 特质波动率 | 价格 | 剔除大盘影响后的残差波动（年化） | window=60（20～250） |
| `skewness` | 收益偏度 | 价格 | 日收益率的偏度，正偏（彩票型）个股长期收益往往偏低 | window=60（20～250） |
| `illiquidity` | 非流动性 | 价格 | Amihud 指标：平均每亿元成交引起的涨跌幅（%） | window=20（5～120） |

**行业**：申万 2021 一级行业（31 个），来自巨潮资讯的行业变更记录，按变更日期生效；分类标准 2021-07 发布，之前的日期沿用最早一条记录（行业很少变化，近似处理）。

财报只在「最早可用日期」之后使用：A股一季报 4/30、半年报 8/31、三季报 10/31、年报次年 4/30（按法定披露截止日，宁晚勿早）。ETF 没有财报，只选 ETF 的策略不能用财报因子。

### 2.3 回测规则

- T 日收盘计算信号，T+1 日开盘成交，开盘价加减 5 个基点滑点；先卖后买。
- 100 股整手；停牌不能交易；开盘即涨停不能买、开盘即跌停不能卖；单笔成交额不超过当日成交额的 10%。
- 佣金按「配置中心 → 交易成本」（默认万 2.5、最低 5 元）；股票过户费十万分之一；股票卖出印花税 2023-08-28 前 0.1%、之后 0.05%；ETF 免印花税和过户费。
- 调仓门槛：新建仓与清仓不受限制；已有持仓的加减仓，目标金额与当前市值之差超过「最小交易比例」才交易（单策略按规格，默认 1%；多风格组合至少 0.5%，避免大量几千元的补仓单）。
- 分红送转与 ETF 份额折算按复权因子调整持股数（分红相当于再投资，近似处理）；股票红利税按持有期从现金扣除（见 1.15）。
- 初始资金 100 万。

## 3. 怎样判断一个策略好不好

### 3.1 指标解释

| 指标 | 含义 | 怎么看 |
|---|---|---|
| 累计 / 年化收益 | 区间总收益 / 折算成每年 | 与基准（沪深300）比较 |
| 超额收益 | 策略累计收益 − 基准累计收益 | 正数表示跑赢指数 |
| 夏普比率 | （年化收益 − 无风险利率 2%）/ 年化波动 | 每承担一单位波动换来多少收益；长期 > 1 已相当好 |
| 卡玛比率 | 年化收益 / 最大回撤 | 每承受一单位最大亏损换来多少收益 |
| 最大回撤 | 从最高点到之后最低点的最大跌幅 | 实盘中最可能让人坚持不下去的数字 |
| 年化换手 | 每年买卖金额 / 平均资产（单边） | 越高成本越高，对滑点越敏感 |
| 年化成本 | 每年费用占资产的比例 | |
| 清仓胜率 | 完整持有中赚钱的比例 | 趋势类策略胜率低但盈亏比高，属正常 |
| 稳健性 | 所有数值参数同时随机浮动 ±20% 后验证夏普的中位数 / 原值 | 越接近 100% 越不依赖参数的偶然取值 |

### 3.2 三段区间

| 区间 | 默认 | 作用 |
|---|---|---|
| 开发期 | 2018～2024（训练 + 验证） | AI 研究与诊断；升级检验在这一段上逐年进行，并做月度显著性检验 |
| 留出 | 2025 至今 | 从不参与优化，诚实反映样本外表现 |
| 实时跟踪 | 选中之后 | 最终检验 |

**挑选建议**：同时看验证、留出、实时跟踪三项；留出期明显差于验证期的版本要警惕；不要只看版本号是否更新。实测中两次升级都出现过「验证变好、留出变差」（PRD 3.8）。

### 3.3 升级标准（全部满足才替换冠军）

1. 开发期夏普高于冠军；
2. 候选月收益按两者波动之比换算到冠军的波动水平后，开发期 7 年中至少一半年份跑赢冠军；
3. 等波动的月度超额在统计上显著：bootstrap 单侧 p ≤ 0.05 ÷ 当前冠军以来累计检验过的候选数（含本轮；v1.9 之前只按本轮候选数）；
4. 开发期最大回撤不超过 25%（冠军本身超过时不比冠军更差即可）；年化换手不超过 20 倍；股票策略至少持有 20 只；
5. 参数 ±20% 扰动后开发期夏普中位数不低于原值的 70%。

## 4. AI 对比（附带功能）

侧边栏「AI 对比」：

| 页面 | 功能 |
|---|---|
| 总览 | 各赛道概况 |
| 赛道 | 创建赛道（市场、股票池、规则集、本金、实时 / 历史回放、日频 / 分钟级、快照 / 工具调用、附带新闻财报、代码匿名化）；报名选手（AI、基线、量化策略）；排行榜、收益曲线、规则、事件、一致性评估、导出与 HTML 报告、复制赛道 |
| 账户详情 | 持仓、订单、成交、资金流水、K 线买卖点、策略演进（AI 的策略笔记与复盘） |
| 决策回放 | 每次决策的完整输入、推理过程、输出与工具调用记录 |
| 对比分析 | 2～5 个选手的收益、五维评分、完整指标、相关性、持仓重合度、前视风险标注、重复实验统计 |
| 进化实验 | AI 每日判断模式下的离线进化实验（训练回放复盘、验证回放检验） |

AI 选手可设置自我进化（定期复盘改写策略笔记）。交易规则支持 A股 / 港股 / 美股、做空与融资（开关控制，含计息、追保、强平）。

### 4.1 使用步骤


侧边栏「AI 对比」下保留 v1.0 的全部功能：多个 AI 与基线选手在同一赛道用虚拟本金模拟交易并对比。量化策略也可以作为选手加入赛道。

1. **配置中心 → 模型供应商**：添加模型（云端填 API Key；本地 Ollama / LM Studio / llama.cpp 填局域网地址），点「测试连接」确认可用。
2. **配置中心 → 选手**：为模型创建选手，可设置 temperature、投资风格、记忆轮数，以及是否「自我进化」。
3. **赛道 → 创建赛道**：选择股票池（默认上证50 + 10 只核心 ETF）、规则集、本金，勾选参赛的 AI 和基线选手。
4. **启动比赛**：启动后股票池、规则和选手冻结。系统在每个交易日收盘后（15:45 起）自动：
   结算上一轮订单（以当日开盘价撮合）→ 记录收盘净值 → 用当日收盘数据请所有选手决策 → 订单在下一交易日开盘撮合。
5. 在**赛道详情**看排行榜与收益曲线，在**账户详情**看持仓、成交和 K 线买卖点，在**决策回放**看每次决策的完整输入、推理与输出。

> 后端需要保持运行才能自动执行；停机错过的交易日会在下次启动时补结算（期间的决策轮次记为「错过」）。

#### 运行方式（日频 / 分钟级）

| | 日频 | 分钟级 |
|---|---|---|
| 决策时点 | 每个交易日收盘后 | 交易时段内，开盘 2 分钟后起每 5 / 15 / 30 / 60 分钟一轮；持仓异动可额外触发 |
| 成交 | 下一交易日开盘价 | 本轮所有选手决策完成后的下一分钟 |
| 行情 | 日线 | 新浪实时行情每 15 秒轮询，合成 1 分钟 K 线 |
| 历史回放 | 支持 | 不支持（港股、美股没有可用的分钟级历史数据） |

#### 自我进化

开启「自我进化」的选手每 N 个交易日（默认 5）在收盘结算后复盘一次：系统把这段时间的收益与基准、回撤、每笔成交及之后的走势、
被拒订单、同赛道排名交给 AI，AI 写出复盘结论和新版「策略笔记」，之后每次决策都会带上最新的策略笔记。

- 策略笔记按参赛账户保存，每个赛道独立演进；复盘只用截至当天收盘的数据，历史回放中也不会看到未来。
- 在**账户详情 → 策略演进**查看复盘记录、每一版的差异，可以立即复盘、手动编辑或回滚。
- 想验证进化是否有效：用同一个模型建两个选手（一个开启、一个不开启），放进同一个赛道对比。

订单类型：市价、限价、止损、止盈；当日有效或长期有效（约 30 个交易日）；买单可附带止损止盈，成交后自动挂出（二者任一成交即撤销另一个）。

#### 做空与杠杆

创建赛道时选择「融资融券 / 孖展与卖空 / 保证金账户」规则集即可开启（只做多规则集不受影响）：

- AI 可以卖空（short）和平空（cover），目标仓位模式下权重为负即做空；开启融资时现金可以为负（融资负债）。
- 总敞口（多头 + 空头市值）不超过净值的 2 倍；每天收盘后计提融资利息和融券费，并检查保证金比率：
  低于维持线发出追保通知（下一轮告诉 AI），下一次检查仍不足或低于强平线则强制平仓（下一交易日开盘成交）。
- 参数三级继承：系统默认 → `config.yaml` 的 `rule_defaults` → 规则集文件；配置中心可以看到每个参数的来源。

#### 对比分析

在「对比分析」页选择 2～5 个选手（可以来自不同赛道），查看收益曲线、五维评分、完整指标、日收益相关性和持仓重合度。
每个结果都标注「实时」或「回放·前视风险」；同一选手在多个赛道的结果会给出均值与标准差（重复实验）。

### 4.2 v1.0 新增功能

- **工具调用模式**：创建赛道时选择「工具调用」，prompt 只列出股票池，AI 自己调用工具查询行情、K 线、指标、财报、新闻和账户，
  最后提交决策；决策回放的「工具调用」标签可以看到每一次查询。需要模型支持函数调用，耗时和 token 明显增加。
- **新闻与财报**：快照模式可选附带财报指标与近 3 日新闻（新闻只在实时运行时提供）。
- **前视偏差防护**：在「配置中心 → 模型供应商」填写模型知识截止日期，回放赛道与对比页会标出风险；回放可开启代码匿名化。
- **风格库**：选手设置的「投资风格」可从 7 种内置风格一键套用（`config/personas.yaml`）。
- **一致性评估**：赛道页「一致性评估」标签，选择评审模型抽样检查 AI 言行是否一致。
- **复制赛道**：一键复制设置与选手，用于重复实验。
- **导出与报告**：赛道页排行榜右上角「导出」，可下载 CSV / JSON 或 HTML 报告。
- **进化实验**：「进化实验」页，在训练区间反复复盘改策略，用之后的验证区间检验进化是否有效（耗时较长）。

## 6. 已知局限

| 局限 | 影响 | 计划（PRD 3.9） |
|---|---|---|
| 历史成分来自 Baostock 每月快照，纳入 / 剔除日期精度约一个月；退市股只有日线与复权因子 | 回测与真实成分略有出入 | 接入逐日成分数据（如 Tushare，需要用户账户） |
| 单因子选股能力弱、行情风格切换快 | AI 优化很难得到显著改进 | 多风格组合分散；以实时跟踪为准 |
| 冲击成本为经验模型（平方根，系数 1.0） | 大资金时的成本只是估计 | 用实盘成交校准 |
| 回测内核与交易引擎是两套实现 | 已用对账与回放校验确认一致（年化差 < 1%），引擎略保守（预留现金、整手向下取整） | 持续对账 |
| 分红按再投资近似；红利税在除息日按建仓至今的持有期扣除 | 继续持有超过 1 年的略多扣税（偏保守）；实盘对照的净值重建也按再投资近似，与真实账户的现金分红略有差别 | 支持导入资金流水 |
| 券商导出格式各不相同 | 个别券商的列名可能识别不了 | 导入时会提示缺少哪些列；可把列名改成常见名称后再导入，或手工录入 |
| 研究模型可能在训练中见过 2025 年行情 | 留出区间不完全「未知」 | 记录模型知识截止日期，实时跟踪为准 |
| 只支持 A股的策略工坊 | | 港股、美股策略库 |
