# 实验设计：不同研究模型做策略优化有没有差别

| 项目 | 内容 |
|---|---|
| 写定时间 | 2026-10-31（北京时间），早于任何一次对比运行；以本文件的提交时间为准 |
| 代码 | `backend/app/quant/model_compare.py` |
| 性质 | **描述性对比**，不做显著性检验：每个模型在每种风格上只跑一次，样本太少，下不了「哪个模型更好」的统计结论 |

## 要回答的问题

AI 研究员（模型）每轮读当前冠军的回测、交易诊断和研究笔记，提出新的候选规则，由程序回测并按升级门槛检验。换一个模型，会不会：

1. 提出的候选更多通过检验、升级更多？
2. 升级后的冠军在**留出期**（模型从来看不到的数据）上更好？
3. 输出格式更稳定、花费和耗时差别多大？

预期（写在看结果之前）：差别不大。之前的经验是开发期的提升大多不能延续到留出期，换模型改变不了这一点。

## 设置

- **模型**：DeepSeek（`deepseek-flash`，按量计费）和本地 Qwen3.8 flash next（llama.cpp，`qwen3.8-flash-next-iq3_xxs`）。原来的 Qwen3.8-27B 已不可用，不参加。
- **起点**：风格库的 7 种风格（价值投资、趋势跟随、均值回归、ETF 轮动、防御稳健、指数择时、质量成长），都从 `config/strategies.yaml` 的初始规则开始。
  - 每个模型各建一套新策略，共 14 条，不带任何研究笔记。
  - 建好后归档，不出现在策略库里，不参加每晚优化，不影响现有策略。
- **流程**：每条策略优化 **10 轮**，每轮 3 个候选。用和正式优化完全相同的提示、检验区间（开发期 2018～2024）、升级门槛与交易成本。
- **顺序**：按风格依次运行，同一风格两个模型连续跑，减小时间差异的影响。

## 记录的指标（每个模型 × 每种风格）

| 指标 | 定义 |
|---|---|
| 可用轮数 | 10 轮中模型输出能解析、有候选的轮数 |
| 候选 | 提出的候选数；其中与已试过的版本重复的数量 |
| 升级 | 升级为冠军的次数 |
| 开发期提升 | 最终冠军相对初始版本的开发期夏普变化 |
| **留出期提升（主要）** | 最终冠军相对初始版本的留出期夏普变化（留出期 2025-01-01 至运行时最新交易日）；没有升级时为 0 |
| 花费与耗时 | token 数、按供应商价格算的花费、总耗时 |

## 怎么报告

- 两个模型各指标的合计 / 平均，以及逐风格的对照表，全部列出。
- 留出期提升：报告两个模型的平均值，以及 7 种风格中哪个模型更高的次数。
- 只有在**至少 6 种风格**上同一个模型的留出期提升更高时，才说「这个模型可能更好」，而且要注明只跑了一次、需要重复验证。其他情况的结论都是「看不出差别」。
- 运行中出现模型服务故障时，故障轮次计入「不可用」，不重跑、不剔除。
